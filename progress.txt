## Codebase Patterns
- Rust toolchain 1.90.0 with edition 2024; cargo is at `~/.cargo/bin/cargo.exe` and must be added to PATH in bash
- Root crate is `memvid-core` (package name); workspace members listed in root Cargo.toml `[workspace]` section
- Default features for memvid-core: `lex`, `pdf_extract`, `simd`
- All 335 lib tests pass with `cargo test -p memvid-core --lib`
- `MemvidError` (in `src/error.rs`) has 40+ variants; each maps to a string code in `bindings/node/src/error.rs` — reuse the same mapping for Python
- `Memvid` is `Send` — safe to move across threads
- Feature-gated variants (e.g., `temporal_track`) require a passthrough feature in bindings Cargo.toml
- Root `.gitignore` has `*.json` — any new JSON files need explicit `!path/to/file.json` negation patterns
- Node bindings at `bindings/node/` serve as the reference implementation — Python bindings should mirror the same API surface
- Each binding module gets its own file (e.g., `write.rs`, `search.rs`) with impl block; register via `pub mod write;` in `lib.rs`
- `MemoryCardBuilder` requires `source_frame_id` and `engine` — use placeholder values for user-facing card insertion
- `LogicMeshStats` is NOT re-exported from `lib.rs` — access via method return type
- `AskContextFragment` and `AskContextFragmentKind` are NOT re-exported from `memvid_core` root — use `memvid_core::types::ask::` path
- For generic `Option<&E>` embedder params, create a `NoEmbedder` dummy impl and pass `None::<&NoEmbedder>`
- `ReaderRegistry` has no top-level `extract` — use `find_reader(&hint)` then `reader.extract(bytes, &hint)`
- Enum↔string conversion: use `serde_json::to_value` / `serde_json::from_value(Value::String(...))` for `#[serde(rename_all = "snake_case")]` enums
- `start_enrichment_worker` takes `Arc<Mutex<Memvid>>` (not `Option<Memvid>`) — use `run_worker_loop` directly with closures
- PyO3 0.23 `PyErr::new` requires owned values in the args tuple (not references); use `(message.clone(),)` not `(&message,)`
- Custom exception attributes: use `err.value(py).setattr("name", value)` after `PyErr::new`
- `guard_memvid!` macro: acquires Mutex lock and checks `Option` is `Some`; export with `pub(crate) use guard_memvid;` for use in other modules
- PyO3 `__exit__` should return `PyResult<bool>` (false = don't suppress exceptions), not `Py<PyNone>`
- Avoid naming a Rust module file `memvid.rs` — it conflicts with `#[pymodule] fn memvid`; use `lifecycle.rs` instead
- PyO3 `multiple-pymethods` feature (+ `inventory` crate) is required to have multiple `#[pymethods]` blocks for the same `#[pyclass]` across files
- Write operations need mutable guard: `let mut lock = guard_memvid!(mut self, py); lock.as_mut().unwrap()`
- `PutOptions::builder()` + `.build()` for put options; `PutManyOpts { ..Default::default() }` for batch options
- `cargo test -p memvid-python` fails with DLL_NOT_FOUND (cdylib needs Python runtime); use `cargo check`/`cargo build` for validation
