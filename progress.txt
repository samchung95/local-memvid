## Codebase Patterns
- Rust toolchain 1.90.0 with edition 2024; cargo is at `~/.cargo/bin/cargo.exe` and must be added to PATH in bash
- Root crate is `memvid-core` (package name); workspace members listed in root Cargo.toml `[workspace]` section
- NAPI-RS v2 used for Node.js bindings (napi = "2" with features ["napi9", "tokio_rt"], napi-derive = "2", napi-build = "2")
- Async NAPI methods use `tokio::task::spawn_blocking` for blocking Rust calls; requires `tokio = { version = "1", features = ["rt"] }` in Cargo.toml
- `JsMemvid` wraps `Arc<Mutex<Option<Memvid>>>` — `guard_memvid!` macro checks for None (CLOSED) and poisoned mutex (INTERNAL)
- `Memvid` is `Send` — safe to move across threads via `spawn_blocking`
- `pub(crate) use guard_memvid;` re-exports the macro for use in sibling modules
- `lock_inner()` function in `memvid.rs` provides non-macro guard for closures where `return Err` doesn't work
- The `MEMVID_CORE_VERSION` constant in `src/lib.rs` provides the version string
- Default features for memvid-core: `lex`, `pdf_extract`, `simd`
- All 335 lib tests pass with `cargo test -p memvid-core --lib`
- `MemvidError` (in `src/error.rs`) has 40+ variants; each maps to a string code in `bindings/node/src/error.rs`
- Feature-gated variants (e.g., `temporal_track`) require a passthrough feature in `bindings/node/Cargo.toml`
- NAPI test runner outputs "Load Node-API ... failed" warnings — these are harmless when running `cargo test` outside Node.js
- Each binding module gets its own file (e.g., `write.rs`) with `#[napi] impl JsMemvid` block; register via `pub mod write;` in `lib.rs`
- NAPI `Buffer` auto-accepts JS `Buffer` and `Uint8Array`; `i64` maps to JS `bigint` for frame IDs
- NAPI `Float32Array` from `napi::bindgen_prelude` maps to JS `Float32Array`; use `.to_vec()` to get `Vec<f32>`
- `FrameRole` has 3 variants: `Document`, `DocumentChunk`, `ExtractedImage` — re-exported from `memvid_core::FrameRole`
- For Rust structs with many fields, use `Option<T>` in JS `#[napi(object)]` structs so omitted fields get Rust defaults
- `#[napi(object)]` structs don't derive `Debug` — use `match` pattern (not `.unwrap_err()`) for `Result<JsStruct, _>` in tests
- Rust `u128` (e.g., `elapsed_ms`) maps to `f64` in JS since NAPI doesn't support u128
